================================================================================
AgenticEDA — Comprehensive EDA Rulebook
================================================================================
Each rule is tagged with: [phase] [topic] [essential|conditional|optional]
"essential"     = always execute
"conditional"   = execute only when a prior check triggers it (trigger noted)
"optional"      = execute if time/context permits; skip does not compromise core EDA

Rules are grouped into phases. Phases 1-4 are SEQUENTIAL (always run in order).
Phases 5+ are CONDITIONAL — the agent selects which sub-phases to run based on
the data profile built in Phases 1-4. Branching logic is noted with GATE rules.

################################################################################
PHASE 1 — INGEST & PARSE
################################################################################

1.  LOAD DATA AND PARSE TIME CORRECTLY: convert the time column to a true
    datetime, sort by time, and SET IT AS INDEX (or keep a dedicated time column
    if the data is panel/long format). FOCUS: the mechanics of turning a raw
    timestamp column into a reliable time axis that all later plots/resampling
    depend on. [ingest] [time-index] [essential]

2.  VERIFY BASIC INTEGRITY: check row counts, duplicate timestamps, duplicate
    entity+timestamp pairs (for panel data), unexpected negative values (if
    impossible), and impossible jumps. FOCUS: catching data-pipeline artifacts
    before they propagate. [ingest] [sanity] [essential]

3.  IDENTIFY THE SERIES STRUCTURE: classify as (A) single series, (B) multiple
    series (panel: entity_id + time), or (C) multivariate (many sensors/features
    per time). Decide the PRIMARY KEY (time) and SECONDARY KEY (entity_id)
    early. [ingest] [schema] [essential]

4.  MAP FEATURE TYPES: separate NUMERIC CONTINUOUS, NUMERIC COUNTS, BINARY
    FLAGS, CATEGORICALS, and KNOWN EXOGENOUS (calendar, price, weather,
    events). Keep a clean list of TARGET vs COVARIATES if applicable.
    [ingest] [feature-typing] [essential]

5.  CHECK TIME RANGE + COVERAGE: compute min/max timestamps, expected
    frequency, and missing time coverage per entity (coverage %, longest gap,
    number of gaps). [ingest] [coverage] [essential]

6.  INFER/CONFIRM SAMPLING FREQUENCY: compute typical time deltas
    (mode/median), detect IRREGULAR SAMPLING, and decide whether to RESAMPLE to
    a regular grid or keep irregular with gap-aware methods.
    [ingest] [frequency] [essential]

################################################################################
PHASE 2 — DATA QUALITY
################################################################################

7.  AUDIT MISSINGNESS TWO WAYS: (1) missing VALUES inside existing timestamps,
    (2) missing TIMESTAMPS (holes in the grid). Track both, because they imply
    different fixes and different model risks.
    [quality] [missingness] [essential]

8.  HANDLE MISSING VALUES WITH INTENT: choose one of: LEAVE AS NaN + add
    missingness flags, FORWARD-FILL, INTERPOLATE, ZERO-FILL (only for true
    counts with meaning), or DROP segments. ALWAYS record what you did and why.
    [quality] [imputation] [essential]

9.  STANDARDIZE UNITS AND SCALE: if features are on wildly different scales
    (common in multivariate sensors), consider robust scaling (median/IQR) or
    log1p for heavy-tailed positive variables. GATE: only if scale disparity or
    extreme tails detected in profiling.
    [quality] [scaling] [conditional]

10. DETECT AND HANDLE DUPLICATES: beyond timestamp duplicates (rule 2), check
    for near-duplicate rows (same entity, same values, different timestamps)
    that may indicate logging errors or double-counting.
    [quality] [duplicates] [essential]

################################################################################
PHASE 3 — UNIVARIATE ANALYSIS
################################################################################

11. START WITH UNIVARIATE SUMMARIES: for each numeric feature compute
    count/mean/std/min/max/quantiles; for panel data do this PER-ENTITY and
    overall to detect "weird entities". [univariate] [stats] [essential]

12. PLOT UNIVARIATE DISTRIBUTIONS: histogram/KDE (or ECDF) for each feature;
    check SKEW, HEAVY TAILS, ZERO-INFLATION, and MULTI-MODALITY. FOCUS:
    quickly learning "what values look normal" and whether transformations will
    be needed. [univariate] [distribution] [essential]

13. TEST / FIT DISTRIBUTIONS WHEN IT MATTERS: if you need transformations or
    probabilistic assumptions, compare candidate fits (e.g., log-normal / gamma
    / Johnson family) and choose a transformation accordingly. FOCUS: using a
    "best-fit distribution" check as a practical trigger for log/Box-Cox-like
    transforms, not as a purity test.
    [univariate] [assumptions] [conditional]
    TRIGGER: skewness > 2 or tail_ratio > 5 or downstream model requires
    normality assumptions.

################################################################################
PHASE 4 — TEMPORAL STRUCTURE (always run for time-series data)
################################################################################

14. PLOT THE RAW TIME SERIES FIRST: line plot of target(s) over time; for
    multivariate data use SMALL MULTIPLES (grid of plots) so you can compare
    shapes and volatility. FOCUS: seeing overall trend + abrupt regime changes
    across many variables at once.
    [time-view] [trend-shifts] [essential]

15. ZOOM INTO WINDOWS: always inspect multiple windows (last week/month, a
    random week, a random day) to detect EVENT SPIKES, DRIFT, regime changes,
    and sensor dropouts that disappear at full scale.
    [time-view] [zoom] [essential]

16. MARK EVENTS / REGIMES VISUALLY: add vertical lines or shaded spans for
    known events, policy changes, maintenance periods, holidays, outages, or
    dataset-defined "eras". FOCUS: adding HUMAN-INTERPRETABLE ANCHORS so
    patterns aren't misread as "random noise."
    [time-view] [events] [conditional]
    TRIGGER: metadata contains event columns, or user supplies event calendar.

17. RESAMPLE TO MULTIPLE GRAINS: compute aggregates at several frequencies
    (hourly->daily->weekly->monthly) using mean/sum/max depending on variable
    type; compare plots to separate NOISE vs SIGNAL. FOCUS: the workflow of
    resampling + plotting to reveal structure hidden at the native sampling
    rate. [time-view] [resampling] [essential]

18. CHECK SEASONALITY EXPLICITLY: compute average by HOUR-OF-DAY, DAY-OF-WEEK,
    WEEK-OF-YEAR, MONTH; plot seasonal subseries; look for multiple
    seasonalities (daily + weekly + yearly). FOCUS: practical "seasonality
    discovery" using grouped averages and seasonal plots.
    [seasonality] [cycles] [essential]

19. DECOMPOSE WHEN USEFUL: use a decomposition (STL or classical
    trend/seasonal/residual) to sanity-check that seasonality is stable and
    residuals look "noise-like". FOCUS: separating TREND vs SEASONAL vs
    RESIDUAL to avoid blaming seasonality for anomalies (or vice versa).
    [seasonality] [decomposition] [conditional]
    TRIGGER: rule 18 detects at least one clear seasonal pattern.

################################################################################
PHASE 5 — DYNAMICS & ROLLING ANALYSIS
################################################################################

20. COMPUTE ROLLING STATISTICS: rolling mean/median/std/min/max (multiple
    window sizes) to reveal CHANGING VARIANCE, local trend, and volatility
    clustering. FOCUS: using rolling summaries as a fast drift/volatility
    detector and as a design guide for lag/rolling features later.
    [dynamics] [rolling] [essential]

21. DETECT CHANGEPOINTS: use statistical changepoint detection (PELT, BOCPD, or
    CUSUM) to identify structural breaks in mean, variance, or trend. FOCUS:
    separating "the data changed regime" from "there's an outlier." Record
    changepoint locations as regime boundaries for downstream analysis.
    [dynamics] [changepoints] [conditional]
    TRIGGER: rolling variance shows >2x change across windows, or visual
    inspection in rule 14/15 flags regime shifts.

22. DETECT OUTLIERS AS "TIME EVENTS", NOT JUST POINTS: flag spikes, level
    shifts, stuck-at plateaus, and sudden variance changes; inspect
    BEFORE/AFTER context windows; decide whether to cap, remove, or label.
    Methods: Z-score on residuals, IQR-based, isolation forest on temporal
    features, or STL residual thresholding.
    [quality] [anomalies] [essential]

################################################################################
PHASE 6 — BIVARIATE & MULTIVARIATE ANALYSIS
================================================================================
GATE: This phase branches based on data structure (rule 3).
  - Panel data  -> run rules 23-24
  - Multivariate -> run rules 25-27
  - Single series with covariates -> run rules 25-27
  - Single univariate series -> skip to Phase 7
################################################################################

23. COMPARE GROUPS (PANEL DATA): group by entity/category (store/item/device/
    customer) and compare distributions (boxplots) and time patterns; identify
    "hard entities" with unusual drift or noise. FOCUS: using per-entity
    comparisons (boxplots + time series) to find heterogeneity and
    segment-specific behavior. [panel] [group-compare] [essential]

24. PANEL HETEROGENEITY TESTS: compute coefficient of variation across entities
    per time step; run Kruskal-Wallis or ANOVA across entity groups to test
    whether entity-level differences are statistically significant. FOCUS:
    deciding whether a single global model suffices or entity-level modeling is
    needed. [panel] [heterogeneity] [conditional]
    TRIGGER: rule 23 shows visible spread across entities.

25. CHECK CROSS-FEATURE CORRELATIONS (MULTIVARIATE): compute correlation matrix
    (Pearson + Spearman, overall and per-window), and look for redundant sensors
    (near-duplicates, |r| > 0.95) and sign flips over time (regime-dependent
    relationships). [multivariate] [correlation] [essential]

26. MUTUAL INFORMATION & NON-LINEAR DEPENDENCIES: for feature pairs where
    Pearson is low but the relationship may be non-linear, compute mutual
    information or distance correlation. FOCUS: catching monotonic and
    non-monotonic associations that linear correlation misses.
    [multivariate] [nonlinear] [conditional]
    TRIGGER: domain expectation of non-linear relationships, or scatter plots
    show curved patterns despite low Pearson r.

27. CHECK LAG RELATIONSHIPS: ACF/PACF for key series; cross-correlation between
    features to spot LEAD-LAG effects and plausible lagged predictors. FOCUS:
    identifying "useful memory length" (how far back lags matter) and lead/lag
    coupling between variables. [dynamics] [lags] [essential]

28. DIMENSIONALITY SCAN: if feature count > 15, run PCA or t-SNE/UMAP for a
    2D/3D projection to check for clusters, outlier groups, or regime
    separation. Record explained variance ratios from PCA. FOCUS: visual
    evidence of latent structure not visible in pairwise plots.
    [multivariate] [dimensionality] [conditional]
    TRIGGER: feature count > 15 or domain suggests latent groupings.

################################################################################
PHASE 7 — INSIGHT DISCOVERY (Inspired by QuickInsights / MetaInsight)
================================================================================
GATE: Run for datasets with >= 2 dimensions (at least one categorical/ordinal
dimension + one measure). Skip for pure univariate time series.
################################################################################

29. AUTOMATED INSIGHT MINING: for each (dimension, measure) pair, compute
    insight scores across types: TREND, OUTLIER, DOMINANCE, EVENNESS,
    CORRELATION, SEASONALITY, CHANGE-POINT. Rank by interestingness score.
    FOCUS: systematic enumeration of "what's interesting" rather than
    cherry-picked charts. (Ref: QuickInsights formulation)
    [insights] [mining] [essential]

30. STRUCTURED KNOWLEDGE EXTRACTION: for top-ranked insights, identify
    COMMONNESS (patterns shared across subgroups) and EXCEPTIONS (subgroups
    that deviate). FOCUS: moving from isolated facts to structured knowledge
    ("most cities peak in summer EXCEPT city X"). (Ref: MetaInsight)
    [insights] [meta-patterns] [conditional]
    TRIGGER: panel data or >= 3 categorical dimension values.

31. DRILL-DOWN ON EXCEPTIONS: for each exception identified in rule 30, drill
    into the subgroup to find the EXPLAINING DIMENSION — the attribute that
    accounts for the deviation. Chain drill-downs up to depth 3.
    (Ref: InsightPilot analysis actions)
    [insights] [drill-down] [conditional]
    TRIGGER: rule 30 identifies at least one exception.

################################################################################
PHASE 8 — CAUSAL & EXPLANATORY ANALYSIS (Inspired by XInsight)
================================================================================
GATE: Run when:
  - Dataset has >= 3 features (need enough variables for a meaningful graph)
  - AND user has not explicitly disabled causal analysis
  - AND dataset has >= 200 rows (causal discovery needs statistical power)
################################################################################

32. CAUSAL GRAPH DISCOVERY: apply a causal discovery algorithm (PC, FCI, or
    GES) to learn qualitative causal structure from observational data. Handle
    functional dependencies by pre-screening with FD detection. Output: a
    partial ancestral graph (PAG) or DAG with edge confidence scores.
    FOCUS: learning "what might cause what" as a skeleton for explanations.
    (Ref: XInsight XLearner module)
    [causal] [graph-discovery] [conditional]

33. CAUSAL vs NON-CAUSAL CLASSIFICATION: for each variable pair relevant to a
    "why query" (e.g., "why is measure M higher in group A than B?"), use the
    causal graph to classify explanatory variables as CAUSAL (on a directed
    path to the target) or NON-CAUSAL (merely correlated). FOCUS:
    distinguishing actionable factors from confounded associations.
    (Ref: XInsight XTranslator module)
    [causal] [explanation-type] [conditional]
    TRIGGER: rule 32 produced a causal graph AND user asks a "why" question
    or an anomaly/exception needs explanation.

34. QUANTIFY CAUSAL RESPONSIBILITY: for causal explanations, compute
    responsibility scores (based on actual causality / counterfactual
    reasoning) to rank which factors contribute most to an observed data fact.
    FOCUS: going from "X causes Y" to "X accounts for 77% of the difference."
    (Ref: XInsight XPlainer module)
    [causal] [responsibility] [conditional]
    TRIGGER: rule 33 identified causal factors.

35. GRANGER CAUSALITY (TIME-SERIES SPECIFIC): for time-series data, test
    pairwise Granger causality between features to detect temporal predictive
    relationships. Use VAR model or transfer entropy as alternatives. Report
    significant (p < 0.05) directional links with lag order.
    [causal] [granger] [conditional]
    TRIGGER: multivariate time series with >= 2 numeric features and
    stationarity confirmed or achieved via differencing.

################################################################################
PHASE 9 — TRAIN / TEST SPLITTING & LEAKAGE VALIDATION
################################################################################

36. TEMPORAL TRAIN/TEST SPLIT: split data chronologically (NOT randomly) using
    a cutoff date. Typical ratios: 70/15/15 or 80/20 (train/val/test).
    For panel data, apply the SAME time cutoff across all entities. Record the
    cutoff date(s) explicitly. NEVER shuffle time-series data.
    [split] [temporal] [essential]

37. CROSS-VALIDATION STRATEGY SELECTION: choose the appropriate CV scheme based
    on data structure:
    - Single series: expanding-window or sliding-window CV
    - Panel data: grouped time-series CV (entities as groups)
    - Non-temporal: stratified k-fold (if classification target exists)
    Record the chosen scheme and its parameters.
    [split] [cv-strategy] [essential]

38. VALIDATE LEAKAGE RISKS: ensure no future information is included in
    features (especially engineered lags/rolling); verify that any
    normalization/scaling is fit ONLY ON TRAINING data. Check for:
    - Target leakage (features derived from the target)
    - Temporal leakage (future values in lag/rolling features)
    - Group leakage (train/test entities sharing information)
    [split] [leakage] [essential]

39. COMPARE TRAIN vs TEST DISTRIBUTIONS: for each key feature, compare
    distributions between train and test splits (KS test, PSI, or visual
    overlay). Flag features with significant distribution shift — these may
    degrade model generalization. FOCUS: detecting dataset drift that makes the
    test set unrepresentative.
    [split] [drift-check] [essential]

################################################################################
PHASE 10 — STATIONARITY & MODEL-READINESS CHECKS
================================================================================
GATE: Run only if downstream modeling is planned (forecasting, regression, etc.)
################################################################################

40. TEST STATIONARITY: run ADF and KPSS tests; inspect rolling mean/variance
    visually. If non-stationary and classical models are planned, apply
    differencing (first-order or seasonal) and re-check. FOCUS: treating
    stationarity as a MODEL-ASSUMPTION GATE, not a ritual.
    [model-readiness] [stationarity] [conditional]
    TRIGGER: downstream model assumes stationarity (ARIMA, VAR, etc.)

41. UNIT ROOT AND COINTEGRATION: for multivariate non-stationary series, test
    for cointegration (Johansen test or Engle-Granger). Cointegrated series can
    be modeled jointly even if individually non-stationary. FOCUS: avoiding
    unnecessary differencing that destroys long-run relationships.
    [model-readiness] [cointegration] [conditional]
    TRIGGER: >= 2 non-stationary series that are theoretically related.

42. CREATE A MINIMAL BASELINE FEATURE SET: calendar features (hour, dow, month,
    is_holiday) + a few lags + rolling stats; verify they align correctly with
    time (no off-by-one). This doubles as an EDA sanity check.
    [model-readiness] [features] [conditional]
    TRIGGER: modeling phase is planned.

43. FEATURE IMPORTANCE SCREENING: compute permutation importance or SHAP values
    from a quick baseline model (e.g., LightGBM) to rank features by
    predictive power. Drop features with near-zero importance. FOCUS: reducing
    noise features before final modeling.
    [model-readiness] [feature-selection] [conditional]
    TRIGGER: feature count > 10 or baseline model is being built.

################################################################################
PHASE 11 — WRAP-UP & REPORTING
################################################################################

44. SUMMARIZE FINDINGS AS ACTIONABLE DECISIONS: record (1) frequency choice,
    (2) missingness strategy, (3) main seasonalities, (4) anomaly types
    present, (5) stable vs drifting features, (6) which entities/features are
    problematic, (7) causal factors identified, (8) train/test split dates and
    any drift detected, (9) recommended modeling approaches.
    [wrap-up] [decisions] [essential]

45. ALWAYS KEEP REPRODUCIBLE PLOTS + METRICS: store the exact parameters for
    resampling windows, rolling windows, anomaly thresholds, and any filtering
    so the agent can rerun and compare across datasets.
    [wrap-up] [reproducibility] [essential]

46. GENERATE STRUCTURED REPORT: produce a report with sections matching the
    phases above. Each section contains: (a) what was checked, (b) what was
    found, (c) what action was taken or recommended. Include key plots inline.
    The report should be exportable as PDF or Markdown.
    [wrap-up] [report] [essential]

47. LOG INSIGHT PROVENANCE: for every insight or conclusion in the report,
    record which rule produced it, which data subset it applies to, and the
    confidence/p-value where applicable. FOCUS: enabling the user to trace any
    claim back to its source computation.
    [wrap-up] [provenance] [essential]

################################################################################
CONDITIONAL BRANCHING SUMMARY
################################################################################
The agent uses the data profile from Phases 1-4 to decide which later phases
and rules to activate. Key decision variables:

  DATA_STRUCTURE (from rule 3):
    single        -> skip rules 23-24; Phase 7 only if exogenous dims exist
    multiple      -> run rules 23-24; Phase 7 fully
    multivariate  -> run rules 25-28; Phase 7 if dims exist

  HAS_COVARIATES (from rule 4):
    yes -> run Phase 6 correlation/lag rules (25-27)
    no  -> skip Phase 6

  FEATURE_COUNT (from rule 4):
    > 15  -> run rule 28 (dimensionality scan)
    > 10  -> run rule 43 (feature importance)
    <= 10 -> skip both

  ROW_COUNT:
    >= 200 -> Phase 8 (causal) eligible
    < 200  -> skip Phase 8

  SEASONALITY_DETECTED (from rule 18):
    yes -> run rule 19 (decomposition)
    no  -> skip rule 19

  REGIME_SHIFTS_DETECTED (from rules 14-15, 20):
    yes -> run rule 21 (changepoint detection)
    no  -> skip rule 21

  MODELING_PLANNED:
    yes -> run Phase 10 (stationarity, cointegration, features, importance)
    no  -> skip Phase 10

  PANEL_HETEROGENEITY_VISIBLE (from rule 23):
    yes -> run rule 24
    no  -> skip rule 24
