# cleanup6.md — Hypothesis-Driven Subagent Architecture

## Vision

After the initial EDA pass (load, clean, plot, basic stats), the agent enters
an **investigation phase** where it:

1. Formulates up to 10 hypotheses/curiosities from what it's seen so far
2. Spawns subagents to investigate each hypothesis independently
3. Each subagent writes cells, executes them, reads outputs, and concludes
4. Subagents can spawn ONE level of sub-subagents if they discover something
5. All findings feed into a knowledge graph
6. The knowledge graph drives a comprehensive story with plot references
7. Any chat-driven changes retrigger story generation

## Subfeature Table

| # | Subfeature | Files | Description |
|---|-----------|-------|-------------|
| A | Hypothesis Generator | `src/agent/hypothesis.py` | LLM reads all findings from pass 1, generates up to 10 ranked hypotheses |
| B | Subagent Runner | `src/agent/subagent.py` | Executes a single hypothesis investigation: writes cells, interprets outputs, can spawn sub-investigations |
| C | Knowledge Graph | `src/agent/knowledge_graph.py` | Accumulates findings from all subagents, deduplicates, tracks evidence chains (finding → cell_id → plot) |
| D | Investigation Orchestrator | `src/agent/eda_agent.py` (update) | After pass 1, calls hypothesis generator, dispatches subagents sequentially, collects into knowledge graph |
| E | Story from Knowledge Graph | `backend/routers/run.py` (update) | Story generated from the knowledge graph, not raw findings list |
| F | Frontend: Investigation Progress | `frontend/src/hooks/useAgentStream.ts` + `NotebookPane.tsx` | Show which hypothesis is being investigated, progress within each |
| G | Frontend: Story Retrigger | `frontend/src/app/session/[id]/page.tsx` + `backend/routers/chat.py` | Chat-driven changes retrigger story generation + version history |
| H | Notebook Section Headers | `src/agent/eda_agent.py` | Each hypothesis gets a clear markdown section header in the notebook |

## Detailed Design

### A. Hypothesis Generator (`src/agent/hypothesis.py`)

- [x] Input: AgentState after pass 1 (columns, dtypes, findings, time_col, numeric_cols)
- [x] LLM call: "Given these initial EDA findings, what are the most interesting
      hypotheses worth investigating? Consider: unexpected correlations, anomalies
      that need explanation, seasonal patterns to decompose, regime changes to
      characterize, causal relationships to test, feature interactions to explore."
- [x] Output: list of `Hypothesis(id, title, description, priority, relevant_cols, eda_rules: list[int])`
- [x] Max 10 hypotheses, ranked by expected insight value
- [x] Each hypothesis references which EDA_RULES.txt rules it addresses
- [x] Example hypotheses:
  - "Wind speed and power output have r=0.978 — is this linear or does it follow a power curve?"
  - "7 outliers in LV ActivePower — are they clustered in time or random?"
  - "Wind direction varies 199-274° — does direction predict power output independently of speed?"

### B. Subagent Runner (`src/agent/subagent.py`)

- [x] Takes: Hypothesis + AgentState + kernel access + push_event callback
- [x] Writes 2-5 cells investigating the hypothesis
- [x] Each cell is generated by the LLM with the hypothesis context
- [x] Reads outputs and interprets them
- [x] Can spawn ONE sub-investigation if findings are surprising (max 2 extra cells)
- [x] Returns: `Investigation(hypothesis_id, cells: list[cell_id], finding: str, plots: list[cell_id], confidence: float, sub_investigations: list)`
- [x] All cells get the hypothesis title as a thinking block so user sees what's being investigated
- [x] Push `phase_transition` event with hypothesis title

### C. Knowledge Graph (`src/agent/knowledge_graph.py`)

- [x] Simple directed graph: nodes are findings, edges are evidence links
- [x] Node types: DataFact, Hypothesis, Evidence, Conclusion
- [x] Each node stores: text, cell_ids (supporting cells), plot_cell_ids, confidence
- [x] Methods:
  - `add_fact(text, cell_id)` — from pass 1
  - `add_investigation(hypothesis, finding, evidence_cells, plot_cells, confidence)`
  - `get_story_sections()` — returns ordered sections with narratives and plot refs
  - `to_dict()` — serializable for storage
- [x] Deduplication: if two findings say the same thing, merge and keep higher confidence

### D. Investigation Orchestrator (update `eda_agent.py`)

- [x] After the goal loop completes (pass 1), enter investigation phase:
  ```
  1. Build knowledge graph from pass 1 findings
  2. Call hypothesis_generator(state, knowledge_graph) → hypotheses
  3. Push phase_transition("Investigation Phase — {n} hypotheses to explore")
  4. For each hypothesis (sequentially):
     a. Push thinking("Investigating: {hypothesis.title}")
     b. Push phase_transition("Hypothesis {i}/{n}: {title}")
     c. Run subagent(hypothesis, state, kernel, push_event)
     d. Add results to knowledge graph
  5. Push phase_transition("Synthesis")
  6. Write summary markdown cell from knowledge graph
  7. Push complete event
  ```
- [x] The investigation phase is clearly separated from pass 1 in the notebook
- [x] A markdown cell "## Investigation Phase" marks the boundary

### E. Story from Knowledge Graph (update `run.py`)

- [x] After agent completes, story is built from knowledge_graph.get_story_sections()
- [x] Each section = one investigated hypothesis with:
  - Title (the hypothesis)
  - Narrative (what was found, in prose)
  - Relevant plots (cell_ids that have images)
  - Confidence level
  - Connected findings (what this hypothesis relates to)
- [x] LLM synthesizes the narrative from the knowledge graph, not raw findings
- [x] Executive summary = top 3-5 most important conclusions from the graph

### F. Frontend: Investigation Progress

- [x] During investigation phase, show in the progress bar:
  "Investigating hypothesis 3/8: Do outliers cluster in time?"
- [x] Chat shows: "→ Investigating: {hypothesis title}" for each
- [x] Notebook gets clear section headers for each hypothesis

### G. User-Driven Hypotheses from Chat

- [x] When user asks "how does X relate to Y?" or "is X causal to Y?", detect this as a hypothesis request
- [x] Create a Hypothesis object from the user's question
- [x] Run the subagent investigation (same as auto-generated hypotheses)
- [x] Add to knowledge graph, retrigger story, save version
- [x] Chat response: "Investigating: {hypothesis}..." then streams cells, then "Found: {conclusion}"
- [x] Update `backend/routers/chat.py`: detect hypothesis-style questions, run subagent
- [x] Update `src/chat/chat_agent.py`: LLM classifies user message as question vs hypothesis request

### G2. Story Retrigger on Chat Changes

- [x] When chat executes code (ACTION block), after execution:
  1. Add the new finding to the knowledge graph
  2. Regenerate story from updated knowledge graph
  3. Save new version in history
  4. Push event so frontend refreshes story
- [x] Frontend: when story store updates, Story tab auto-refreshes

### H. Notebook Section Headers

- [x] Pass 1 goals get headers: "## Data Loading", "## Data Cleaning", etc.
- [x] Investigation phase gets: "## Investigation Phase"
- [x] Each hypothesis gets: "### Hypothesis: {title}"
- [x] Summary gets: "## Conclusions"

## Implementation Plan

- Agent A: hypothesis.py + knowledge_graph.py (backend, no frontend)
- Agent B: subagent.py (backend, no frontend)
- Agent C: frontend progress updates + story retrigger

### Wave 2 (depends on Wave 1):
- Update eda_agent.py orchestrator (needs A + B)
- Update run.py story generation (needs A)
